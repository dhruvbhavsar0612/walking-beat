# Limitations register

One row per known limitation — technical, clinical, UX, or regulatory. Rule: **every limitation
here needs a mitigation and, where user-facing, an in-app disclosure.** This register is the
source of truth for the onboarding limitations screen, the About screen, investor Q&A, and the
regulatory risk file (when it exists). Never let marketing text contradict this table.

## How to use this file

- **In-app:** limitations screen text must stay consistent with L1–L4 wording.
- **Pitch/deck:** quote L1, L2 honestly — investors respect a team that knows its walls.
- **Regulatory:** L11 is the gate; L1–L3 data becomes the clinical evaluation file.
- **Every new feature PR:** add/limitation check — if a change adds a limitation, add a row.
